# 읽기 전용 게시 사용법 · v3

## 로컬 장부와 게시본

학생·계약·거래·변경 이력은 기존 IndexedDB에 그대로 있습니다. 게시 과정은 장부를 수정하지 않습니다. 게시 파일은 그 시점의 자리 번호, 소유주/임차인 표시 이름, 임대 유형, 현재 시세, 선택한 시세 이력, 모둠 이름만 담습니다. 계약 금액·특약·원본 ID·백업·사진은 제외합니다. 익명이 기본값이며 별칭 또는 실명을 명시적으로 선택할 수 있습니다. 모둠 이름과 자리 번호에 개인정보를 적었다면 미리보기에서 확인하세요.

게시본은 학생 로그인이나 채팅 서버가 없는 독립 HTML입니다. 캐릭터와 말풍선은 실제 학생과 무관한 장식입니다. 게시한 뒤 로컬 장부를 변경해도 자동 반영되지 않습니다. 다시 미리보기를 만들고 같은 경로에 게시하면 갱신됩니다.

## 파일로 게시

1. 설정 → 읽기 전용 게시본 만들기.
2. 이름 공개 방식과 시세 그래프 포함 여부를 선택합니다.
3. 미리보기 만들기 → 크게 보기에서 내용을 확인합니다.
4. 공개 확인을 체크하고 classroom.html을 다운로드합니다.
5. 정적 웹 호스팅에 해당 파일만 올리고 그 주소를 공유합니다. 공개용 파일은 더블 클릭으로도 볼 수 있습니다. 원본 관리 앱은 npm run dev 또는 웹 서버가 필요합니다.

## 앱에서 GitHub Pages로 직접 게시

1. 장부 백업을 올리지 않는 별도 공개용 저장소를 준비합니다.
2. 저장소 Settings → Pages에서 Deploy from a branch를 선택하고 브랜치 및 /(root) 또는 /docs를 설정합니다.
3. 해당 저장소로 범위를 한정한 접근 토큰에 Contents 쓰기와 Pages 읽기 권한을 부여합니다. 토큰은 채팅에 보내지 말고 앱의 접근 토큰 칸에 입력합니다.
4. 게시 미리보기를 확인한 뒤 GitHub Pages에 직접 게시를 펼쳐 계정/저장소와 토큰을 입력하고 공개 게시 / 갱신을 누릅니다.
5. 앱은 Pages 설정에 따라 published/classroom.html 또는 docs/published/classroom.html 하나만 생성·갱신합니다. 관리 표시가 없는 기존 파일은 덮어쓰지 않습니다. 다른 곳에서 동시에 변경한 경우 충돌을 알립니다.
6. 저장 완료는 배포 완료와 다릅니다. GitHub의 Pages 배포가 성공한 후 표시된 주소를 열어 확인하세요. GitHub Actions 방식의 Pages는 이 직접 게시 기능에서 지원하지 않으며 다운로드 파일을 기존 배포 흐름에 포함하면 됩니다.

토큰은 입력 화면의 메모리에만 존재하며 게시 시도 후 지웁니다. IndexedDB, 백업, 게시 파일에 저장하지 않습니다. 공개 파일의 콘텐츠 보안 정책은 외부 통신을 차단합니다. 게시 취소는 GitHub에서 해당 파일을 삭제하고 Pages 재배포를 기다립니다. 이전 Git 기록·캐시·다른 사람이 내려받은 사본까지 삭제되지는 않습니다.

실제 저장소와 토큰을 제공받지 않았으므로 원격 업로드/Pages 배포 완료는 실계정으로 검증하지 않았습니다. 생성·갱신·충돌·잘못된 대상 차단은 모의 API 테스트로 검증했습니다.

공식 참고: [GitHub Contents API](https://docs.github.com/en/rest/repos/contents), [Pages API](https://docs.github.com/en/rest/pages/pages).

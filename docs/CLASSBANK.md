# ClassBank 공통 규격 및 연동 안내

규격: `classbank-property-exchange`, 버전: `1.0.0`. 소스: `classbank` 또는 `property-service`.

첨부 명세의 학생·자리·계약·거래·시세 이력·기간 필드와 필드명을 유지했습니다. 아래 선택 확장 필드는 양쪽 서비스에 동일하게 적용해야 합니다. 규격을 이미 독립적으로 운영하는 ClassBank가 있다면 배포 전에 합의된 버전 정책을 먼저 확인하세요.

|필드|규칙|
|---|---|
|학생 revision / updatedAt|선택. 로컬 수정 시 생성. 외부 입력에서 누락된 값은 임의 보충하지 않음|
|자리·계약·거래 updatedAt|선택 ISO timestamp. 충돌 자동 해결의 근거로 사용하지 않음|
|자리 initialOwnerId|선택. 첫 계약 전 소유자. null은 미지정. 매매 취소 및 이력 재계산에 필요|
|자리 initialSalePrice|선택. 계약 이력 이전 최근 매매가. 모르면 null|
|계약 endedAt|선택 날짜. 임대차 status=ended이면 필수. 조기 종료 시점 보존|

## 타입와 검증

`shared/exchange.ts`와 `src/domain.ts`를 같은 패키지 또는 동일한 파일로 두 프로젝트에서 사용합니다. Zod 4 의존성이 필요합니다. `exchange.schema.json`은 언어 중립적인 **구조 검증**용입니다. 교차 참조, 중복 ID, 소유권 연결, 임대차 기간 충돌, 날짜 실제 존재 여부는 TypeScript 검증기를 함께 실행해야 합니다. JSON Schema 단독 검증은 충분하지 않습니다.

```ts
import { validateExchange } from './shared/exchange';
import { assertBusiness } from './src/domain';
const parsed = validateExchange(JSON.parse(text));
assertBusiness(parsed);
```

`validateExchange`는 입력을 새 객체로 파싱하고 필드 형식·참조·중복·기간 충돌을 검증합니다. 알 수 없는 필드는 공통 규격에 넣지 않습니다. ClassBank의 은행 장부 데이터는 이 교환 파일과 별도로 유지하세요.

## 식별자 및 금액

- 학생 이름, 자리번호와 ID는 별개입니다. 이름 수정, 정렬, 내보내기에서 ID를 새로 만들지 않습니다.
- `exportId`만 내보낼 때 새로 생성합니다. 수정한 객체의 ID와 최초 생성한 거래기록 ID는 유지합니다.
- 금액은 유한한 0 이상 숫자이며 단위는 권입니다. 전세·월세 금액을 매매가에 섞지 않습니다.
- 날짜는 실제로 존재하는 `YYYY-MM-DD`, 시각은 시간대가 있는 ISO 문자열입니다.
- 계약·자리·거래의 revision은 양의 정수입니다. 학생의 revision은 기존 예시와의 호환을 위해 선택입니다.
- null은 값 없음이고, CSV의 빈 칸은 기존 필드를 유지하라는 의미입니다.

## 계약과 거래기록

계약 하나당 거래기록은 최대 하나입니다. 계약 금액·날짜를 수정하면 **같은 거래 ID**의 정보를 수정합니다. 변경 전후 전체 상태는 별도 로컬 감사 이력에 기록합니다. 취소·종료 후에도 거래기록을 삭제하지 않으며 집계할 때 계약 상태를 참조합니다. 외부 파일에 거래기록이 없다면 가져오기에서 임의 생성하지 않습니다.

매매 계약은 buyerId가 필요하며 sellerId는 최초 무소유 자리 이전일 때만 null일 수 있습니다. 임대차는 landlordId·tenantId가 필요합니다. 해당 거래와 관계없는 당사자 필드는 null입니다. 임대차 시작일 소유자와 임대인이 같아야 합니다. 종료일 포함 중복 임대차와 임대차 기간 내 매매는 차단합니다.

## 안전한 가져오기

1. 구조·참조 검증 후 classId를 비교합니다. 다른 학급은 병합하지 않습니다.
2. ID별 신규 / 동일 / 충돌을 표시합니다. 공통 조상이나 해시가 없는 서로 다른 데이터는 revision이 커도 충돌입니다.
3. 사용자에게 현재 값과 입력 값을 보여주고 유지 / 적용 / 건너뛰기를 선택하게 합니다.
4. 선택 결과 전체를 재검증합니다. 계약·거래·자리 소유권이 함께 맞아야 적용됩니다.
5. IndexedDB 단일 readwrite 트랜잭션에서 이전 상태 백업과 새 상태를 저장합니다. 실패하면 기존 상태가 유지됩니다.

가져온 데이터에 없는 로컬 객체는 삭제하지 않습니다. 시각만 비교한 last-write-wins를 사용하지 않습니다. 재가져오기는 같은 ID를 다시 생성하지 않습니다. 필드 순서는 정규화해 비교합니다. 확장 필드 유무가 다르면 보수적으로 충돌이 보일 수 있습니다.

## ClassBank에 적용할 체크리스트

1. 공통 타입·검증기·업무 규칙 파일을 동일한 공유 패키지로 연결합니다.
2. ClassBank 학생 ID와 자리 ID를 그대로 사용합니다. 사용자 이름으로 매칭하지 않습니다.
3. `source`만 classbank로 설정해 전체 학급 교환 데이터를 생성합니다.
4. 확장 필드 initialOwnerId/initialSalePrice/endedAt 및 revision/updatedAt을 왕복 보존합니다.
5. 미리보기·승인·원자 저장 흐름을 동일하게 적용합니다.
6. 실제 파일을 양방향으로 왕복하여 null, ID, 계약 상태, 좌표, 이력을 검증합니다.

공통 JSON에는 이미지와 로컬 감사 스냅샷이 없습니다. 이미지 포함 전체 백업은 `classroom-property-local-v1`로 별도 제공되며 ClassBank 교환 파일이 아닙니다.

## CSV

UTF-8 BOM, RFC4180 방식 따옴표/쉼표/줄바꿈을 지원합니다. 자료 종류를 먼저 선택합니다. 기존 객체는 id와 바꿀 열만 있어도 되지만 신규 객체는 필수 필드 전체가 필요합니다. position은 JSON 문자열입니다. 수식으로 해석될 수 있는 셀은 내보내기 시 앞에 작은따옴표를 붙입니다. 이 보안 변환이 필요한 특수 이름의 완전한 왕복에는 JSON을 사용하세요.

CSV는 단일 테이블의 부분 수정용입니다. 계약 CSV는 계약 등록·수정과 같은 업무 규칙으로 소유권과 거래기록 변경안도 생성하며 미리보기에 함께 표시합니다. 관련 항목을 함께 승인해야 합니다. 공통 JSON은 입력에 없는 거래기록을 생성하지 않습니다.

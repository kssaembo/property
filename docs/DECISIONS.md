# 동작 기준과 개선 제안

## 이번 구현의 기준

- 최초 낙찰가격·최근 매매가·현재 시세를 구분합니다. 시세 자동 반영은 기본 꺼짐이며 매매 취소가 시세 기록을 삭제하지 않습니다.
- 임대차 종료일은 사용일에 포함됩니다. 매매를 위해서는 그 전날까지 임대차를 종료해야 합니다.
- 매매 종료는 완료된 계약의 행정적 종료입니다. 소유권은 유지됩니다. 취소만 소유권을 이전 상태로 되돌립니다.
- 후속 매매가 있다면 선행 매매 취소/수정으로 소유권 연결이 깨지는 것을 막습니다. 후속 계약부터 취소하거나 일관된 전체 JSON을 준비하세요.
- 동일 자리의 하루 두 번 매매와 미래 매매는 지원하지 않습니다. 시간 순서를 다루는 스키마 확장 전까지 모호함을 차단하기 위한 제한입니다.
- 임대차 승계 매매는 지원하지 않습니다. 기존 임대차를 종료한 뒤 소유권을 이전하고 필요하면 새 계약을 만듭니다.
- 원본에 initialOwnerId가 없으면 첫 매매의 sellerId로 최초 소유권을 추론합니다. 첫 매매 이전 최근 매매가는 알 수 없어 null로 보존합니다. 완전한 복원 가능성을 위해 두 필드를 양쪽에서 보존하세요.
- 계약 수정 이력은 로컬 감사 스냅샷에 모두 남고, 공통 파일에는 계약 최신 상태와 안정적인 ID만 들어갑니다. 감사 이력 전달은 전체 백업/이력 다운로드를 사용합니다.
- 기간 시작 참고 현황은 실제 계약 장부와 분리됩니다. 배치도만 복사/빈 기간은 참고 스냅샷을 비우는 의미이며 기존 소유권을 초기화하지 않습니다.
- 브라우저 간 동기화, 권한 구분, 암호화 백업, 다중 학급 전환은 포함하지 않습니다.
- 데이터 입력 검증 실패는 화면에 표시되며 자동으로 데이터를 수정하지 않습니다. 잘못된 JSON은 미리보기 전에 차단됩니다.

## 다음 개선 권장순서

1. **ClassBank 공유 패키지 적용과 실제 왕복 검증**: 두 프로젝트가 공통 모듈을 직접 참조하도록 구성하고 실제 익명화 파일로 호환성 테스트를 추가하세요.
2. **공통 기준 버전 동기화**: 객체 해시와 마지막 합의 버전을 교환하면 지금의 보수적인 충돌 확인을 줄일 수 있습니다. 양쪽 규격을 함께 갱신해야 합니다.
3. **새 학년도 작업공간**: 학급별 독립 장부와 기간 시작 소유자 재설정을 별도 개념으로 분리하면 과거 계약을 훼손하지 않고 새 장부를 만들 수 있습니다.
4. **백업 주기 알림**: 마지막 파일 백업 시간을 표시하고 학생 개인정보가 포함된 백업의 암호화 옵션을 추가할 수 있습니다.
5. **대규모 이력 최적화**: 현재는 변경 전후 전체 상태를 보관합니다. 규모가 커지면 변경분 저장·스냅샷 주기 조절로 IndexedDB 용량을 줄이세요.
6. **접근성 확장**: 키보드만으로 마커를 미세 이동하는 기능과 모달 포커스 고정을 보완하면 더 다양한 사용 환경에 적합합니다.

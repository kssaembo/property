# 학급 부동산 거래 서비스 개발 프롬프트

## 0. 개발 목적

초등학교 학급에서 사용하는 독립적인 **부동산 거래 관리 서비스**를 개발한다.

학급에서는 이미 자리 경매가 종료되어 학생들이 각 자리의 소유권을 가지고 있다.

따라서 이 서비스는 경매를 진행하는 프로그램이 아니다.

학생들이 소유한 자리의 매매·전세·월세 거래를 관리하고, 자리 배치도 위에서 현재 소유자, 사용자, 시세, 거래가격, 임대차 현황 등을 확인하는 서비스이다.

핵심 기능은 다음과 같다.

1. 교실 자리 배치도 이미지 표시
2. 자리별 부동산 정보 조회
3. 매매·전세·월세 계약 등록 및 수정
4. 자리별 시세와 거래가격 관리
5. 과거 거래 기록 조회
6. 학생별 부동산 소유 현황
7. 거래 기간별 기록 관리
8. JSON 가져오기 및 내보내기
9. CSV 가져오기 및 내보내기
10. ClassBank 부동산 데이터와 양방향 파일 연동
11. 별도 백엔드 없는 로컬 저장

개발의 가장 중요한 원칙은 **단순성, 안정성, 직관적인 UI, ClassBank와의 데이터 호환성**이다.

---

# PART 1. 기술 구조

## 1. 개발 환경

- React
- TypeScript
- Vite
- 정적 웹사이트로 배포 가능
- 반응형 웹 디자인
- 별도 서버 및 Supabase 연동 없음
- 데이터 저장: 브라우저 IndexedDB
- JSON 파일 백업 및 복원
- CSV 파일 가져오기·내보내기 지원

기존 ClassBank와 직접 API 통신하지 않는다.

ClassBank와는 파일을 통해서만 데이터를 교환한다.

서비스 최초 접속 시 별도 로그인 없이 이용할 수 있도록 한다.

단, 별도 인증 시스템이 없는 만큼 실제 학생 데이터를 공개 서버나 소스코드에 포함하지 않는다. 브라우저별 로컬 데이터는 다른 사용자와 자동으로 공유되지 않는다는 점을 안내한다.

# PART 2. 메인 화면 디자인

## 2. 서비스 명칭

가칭: **우리 반 부동산 거래소**

경매 서비스가 아니라 현재 보유 중인 부동산을 관리하고 거래하는 서비스라는 점이 드러나도록 한다.

전체 디자인은 고급스럽고 세련된 부동산 정보 플랫폼 느낌으로 구성한다.

과도한 애니메이션이나 복잡한 기능은 배제한다.

### 기본 레이아웃

상단:
- 서비스 명칭
- 현재 거래 기간
- 전체 자리 수
- 평균 시세
- 최고 거래가격
- 거래 건수
- 가져오기
- 내보내기
- 설정

중앙:
- 교실 자리 배치도 이미지
- 자리별 클릭 가능한 정보 마커
- 자리별 현재 상태 표시

우측 또는 하단:
- 선택한 자리의 세부정보
- 거래 이력
- 계약 등록·수정
- 시세 수정

추가 메뉴:
- 전체 부동산
- 학생별 보유 현황
- 거래 내역
- 기간별 통계

### UI 원칙

1. 자리 배치도가 화면의 중심이 되어야 한다.
2. 각 자리의 번호와 가격이 쉽게 보이도록 한다.
3. 카드나 정보 패널은 과도하게 크지 않게 한다.
4. 화면 크기에 따라 배치도를 확대·축소할 수 있도록 한다.
5. 기존 학급용 금융 서비스와 어울리도록 고급스럽고 직관적인 스타일을 적용한다.
6. 실제 데이터가 없는 경우 예시 데이터가 자동 등록되지 않도록 한다.

# PART 3. 자리 배치도 관리

## 3. 이미지 업로드

사용자가 교실 자리 배치도 이미지를 업로드할 수 있도록 한다.

지원 형식:
- PNG
- JPG
- WEBP

업로드한 이미지는 IndexedDB에 저장한다.

이미지를 교체해도 자리정보 및 거래내역은 보존되도록 한다.

### 자리번호 마커 배치

배치도 이미지 위에 자리번호를 지정할 수 있는 편집 모드를 만든다.

예시:

1. [자리 위치 편집] 클릭
2. 배치도 이미지에서 책상 위치 클릭
3. 자리번호 입력 또는 기존 자리 선택
4. 해당 위치에 자리번호 마커 생성
5. 드래그로 위치 수정
6. 저장

자리 위치는 이미지의 픽셀값이 아닌 상대 좌표(0~1 또는 0~100%)로 저장한다.

이미지 확대·축소 및 화면 크기 변경에도 마커 위치가 유지되도록 한다.

### 마커 정보

자리마다 다음 정보를 표시할 수 있도록 한다.

- 자리번호
- 현재 시세
- 현재 소유자
- 임대차 상태

표시 항목은 설정에서 켜거나 끌 수 있도록 한다.

자리 클릭 시 상세정보 팝업 또는 패널을 연다.

# PART 4. 자리별 부동산 정보

## 4. 기본정보

각 자리는 고유한 자리 ID를 가진다.

필수 정보:
- 자리 ID
- 자리번호
- 현재 소유자
- 현재 사용자
- 현재 시세
- 최초 낙찰가격
- 최근 매매가격
- 계약 상태
- 자리 배치도상의 위치

### 가격 구분

반드시 다음을 구분한다.

**최초 낙찰가격**
처음 경매에서 해당 자리가 낙찰된 가격

**최근 거래가격**
실제로 마지막으로 매매된 가격

**현재 시세**
현재 자리의 가치에 대해 사용자가 책정한 참고가격

**전세금**
현재 전세 계약의 거래금액

**월세금**
현재 월세 계약의 거래금액

최근 거래가격이 변경되었다고 해서 현재 시세를 무조건 덮어쓰지 않는다.

시세 자동 업데이트 기능은 선택적으로 제공하되 기본값은 수동 수정이다.

# PART 5. 부동산 계약 관리

## 5. 계약 종류

자리 상세정보에서 다음 계약을 등록할 수 있도록 한다.

- 매매
- 전세
- 월세

계약별로 입력 항목이 달라지도록 한다.

### 매매 계약

입력:
- 자리번호
- 매도인
- 매수인
- 총 매매대금
- 계약일
- 특약사항

매매 계약이 유효하게 등록되면 현재 소유자와 최근 매매가격을 갱신한다.

기존 소유자를 포함한 과거 매매 기록은 보존한다.

### 전세 계약

입력:
- 자리번호
- 임대인
- 임차인
- 전세금
- 계약 시작일
- 계약 종료일
- 특약사항

전세 계약 시 소유권은 임대인에게 유지한다.

현재 사용자는 임차인으로 표시한다.

학급의 전세 규칙은 실제 주택 전세와 다를 수 있으므로, 전세금 반환 여부 등은 특약사항에 명시할 수 있도록 한다.

**계약 종료 시 자동 환급 기능은 만들지 않는다.**

### 월세 계약

입력:
- 자리번호
- 임대인
- 임차인
- 월세금
- 납부주기
- 계약 시작일
- 계약 종료일
- 특약사항

월세 계약에서도 소유권은 임대인에게 유지한다.

현재 사용자는 임차인으로 표시한다.

**월세 자동송금 기능은 만들지 않는다.**

### 계약의 기본 기능

- 등록
- 수정
- 종료
- 취소
- 상세조회
- 거래이력 확인
- 계약정보 내보내기

기존 계약 기록을 완전히 삭제하기보다는 상태를 변경해 이력을 남기는 방식을 우선한다.

중복 소유권이나 같은 기간의 충돌하는 임대차 계약이 발생하지 않도록 확인한다.

계약 수정 시 관련 자리의 현재 상태도 함께 갱신한다.

# PART 6. 학생별 부동산 관리

## 6. 학생 목록

학생 목록을 그리드 또는 테이블 형태로 표시한다.

학생 이름 클릭 시 다음을 조회할 수 있도록 한다.

- 소유한 자리
- 사용 중인 자리
- 매매 참여 내역
- 전세 계약 내역
- 월세 계약 내역
- 누적 매매금액
- 등록된 계약정보

학생은 내부적으로 고유 ID를 사용한다.

같은 이름의 학생이 있어도 서로 다른 학생으로 구분할 수 있어야 한다.

### 공동투자

공동투자 및 지분율 기능은 개발하지 않는다.

각 자리의 대표 소유자 1명만 관리한다.

학생 간 공동투자는 개인 간 거래로 처리하며 필요한 경우 특약사항에 기록한다.

# PART 7. 거래 기록 및 시세 관리

## 7. 거래내역

모든 매매·전세·월세 계약의 변경 이력을 보관한다.

거래내역에는 다음을 표시한다.

- 거래일
- 자리번호
- 거래유형
- 거래금액
- 거래 당사자
- 계약 상태

거래유형별 필터와 자리번호 검색 기능을 제공한다.

### 시세 관리

시세는 교사가 직접 수정할 수 있도록 한다.

시세 변경 시 이전 시세도 기록할 수 있도록 한다.

시세 변동 기록을 기반으로 간단한 그래프를 표시한다.

### 통계

- 전체 자리 수
- 매매 완료 자리 수
- 전세 계약 수
- 월세 계약 수
- 현재 임대 중인 자리 수
- 평균 매매가격
- 최고·최저 매매가격
- 평균 시세

통계는 실제로 등록된 데이터를 기준으로 계산한다.

데이터가 없으면 0 또는 자료 없음으로 표시한다.

# PART 8. 거래 기간 관리

## 8. 월별 거래 기간

현재 거래정보와 과거 거래정보를 구분할 수 있도록 한다.

예:
- 2026년 11월
- 2026년 12월

[새 거래 기간 만들기] 기능을 제공한다.

새 기간을 생성할 때 다음 중 선택할 수 있도록 한다.

1. 기존 자리 배치도와 소유 현황을 이어서 사용
2. 자리 배치도만 복사하고 소유 현황은 새로 설정
3. 완전히 빈 기간 만들기

과거 기간의 거래 기록은 보존한다.

기간 변경은 과거의 실제 계약을 삭제하거나 임의로 종료시키는 작업이 되어서는 안 된다.

기간은 조회와 관리의 편의를 위한 분류로 사용한다.

# PART 9. ClassBank와 공통으로 사용하는 JSON 규격

## 9. 최우선 요구사항

**이 서비스와 ClassBank가 완전히 동일한 JSON 데이터 교환 규격을 사용해야 한다.**

각 서비스가 서로 다른 형식으로 JSON을 생성하지 않도록 한다.

공통 규격 명칭:

`classbank-property-exchange`

규격 버전:

`1.0.0`

두 서비스에서 파일을 교환할 때 동일한 필드명과 자료형을 사용한다.

가능하다면 아래 규격을 별도의 TypeScript 타입 정의와 검증 스키마로 작성한다.

ClassBank 프로젝트에도 동일한 규격을 제공한다.

### 공통 JSON 데이터 구조

```json
{
  "format": "classbank-property-exchange",
  "schemaVersion": "1.0.0",
  "classId": "class-2026-6-1",
  "exportId": "export-unique-id",
  "exportedAt": "2026-11-12T15:00:00+09:00",
  "source": "property-service",
  "students": [
    {
      "id": "student-001",
      "name": "김학생"
    }
  ],
  "properties": [
    {
      "id": "seat-001",
      "seatNumber": "1",
      "ownerId": "student-001",
      "occupantId": "student-001",
      "auctionPrice": 100,
      "latestSalePrice": 120,
      "marketPrice": 130,
      "position": {
        "x": 0.35,
        "y": 0.45
      },
      "revision": 1
    }
  ],
  "contracts": [
    {
      "id": "contract-001",
      "propertyId": "seat-001",
      "type": "sale",
      "buyerId": "student-001",
      "sellerId": null,
      "landlordId": null,
      "tenantId": null,
      "amount": 120,
      "paymentCycle": null,
      "contractDate": "2026-11-12",
      "startDate": "2026-11-12",
      "endDate": null,
      "terms": "",
      "status": "active",
      "revision": 1
    }
  ],
  "transactions": [
    {
      "id": "property-tx-001",
      "contractId": "contract-001",
      "propertyId": "seat-001",
      "type": "sale",
      "amount": 120,
      "date": "2026-11-12",
      "revision": 1
    }
  ],
  "marketHistory": [
    {
      "id": "market-001",
      "propertyId": "seat-001",
      "price": 130,
      "recordedAt": "2026-11-12T15:00:00+09:00"
    }
  ],
  "periods": [
    {
      "id": "period-2026-11",
      "label": "2026년 11월",
      "startDate": "2026-11-01",
      "endDate": "2026-11-30"
    }
  ]
}
```

위 데이터는 규격을 설명하기 위한 예시이며 실제 학생정보가 아니다.

### JSON 규격 설계 원칙

1. `format`과 `schemaVersion`은 필수이다.
2. `classId`가 다른 파일은 자동 병합하지 않는다.
3. 학생과 자리, 계약, 거래 기록에는 고유 ID를 사용한다.
4. 날짜는 ISO 형식으로 저장한다.
5. 금액은 '권' 단위의 숫자로 저장한다.
6. ID는 표시 이름이나 배열 순서에 의존하지 않는다.
7. `source`는 `classbank` 또는 `property-service`를 사용한다.
8. `revision`을 이용해 자료 변경 여부를 확인할 수 있도록 한다.
9. 실제 구현에서는 각 자료의 변경 시각과 수정 이력을 별도로 관리하여 두 서비스에서 같은 자료를 수정했을 때 충돌을 감지한다.
10. 데이터를 내보낼 때 새로운 학생 ID나 계약 ID를 임의로 다시 만들지 않는다.
11. ClassBank 고유 ID가 있는 경우 반드시 유지한다.
12. 양 서비스에서 공통 JSON을 직렬화하고 검증할 때 동일한 규칙을 적용한다.

### 추가 기술 요구사항

위 구조는 교환 규격의 기본 예시이다.

실제 개발 시에는 가져오기 안전성을 위해 다음 항목을 보완한다.

- 각 객체의 고유 ID와 수정 시각
- 이전 버전과의 충돌 판별 기준
- 취소·종료된 계약의 상태
- 필요한 경우 삭제 대신 사용하는 종료 또는 삭제 표시
- 원본과 동일한 ID의 중복 객체 방지

**최종 스키마를 변경해야 한다면 독립 서비스와 ClassBank의 스키마를 반드시 함께 수정한다.**

원본 데이터에 없는 정보는 임의로 만들어 넣지 않는다.

# PART 10. 데이터 내보내기

## 10. JSON 내보내기

[데이터 내보내기] 버튼을 제공한다.

버튼 클릭 시 현재 학급의 부동산 관련 데이터를 공통 JSON 형식으로 다운로드한다.

파일명 예시:

`ClassBank_부동산_2026-11-12.json`

내보내기에는 다음 정보를 포함한다.

- 학생 식별정보
- 자리정보
- 소유자 및 사용자
- 매매·전세·월세 계약
- 거래 기록
- 현재 시세
- 시세 이력
- 거래 기간
- 자리 마커 위치

JSON은 ClassBank에서 바로 가져올 수 있는 형식이어야 한다.

내보내기 실행 시 현재 화면에 표시된 자료뿐 아니라 해당 학급의 전체 부동산 기록을 대상으로 한다.

### CSV 내보내기

엑셀에서 확인하기 위한 CSV 내보내기도 제공한다.

CSV는 필요한 경우 계약정보, 자리정보, 거래내역을 각각 별도의 파일로 다운로드할 수 있도록 한다.

CSV는 보조 형식으로 사용한다.

**ClassBank와 양방향으로 완전한 데이터를 교환하는 기본 형식은 JSON이다.**

### Markdown 내보내기

선택 기능으로 부동산 거래 현황 보고서를 Markdown 형식으로 다운로드할 수 있다.

Markdown은 데이터 복원용이 아니라 열람·공유용이다.

# PART 11. 데이터 가져오기

## 11. 공통 JSON 가져오기

[데이터 가져오기] 버튼을 제공한다.

ClassBank에서 내려받은 JSON 파일을 업로드하면 해당 파일의 부동산 정보를 현재 서비스에 반영한다.

### 가져오기 절차

1. JSON 파일 선택
2. 규격 및 버전 확인
3. 학급 ID 확인
4. 학생 ID 매칭
5. 자리 ID 확인
6. 기존 계약과 신규 계약 비교
7. 변경사항 미리보기
8. 충돌 항목 확인
9. 사용자 최종 승인
10. 데이터 저장

### 변경사항 미리보기

다음과 같이 분류하여 표시한다.

- 신규 등록
- 기존 정보 수정
- 변경 없음
- 충돌 발생
- 검증 실패

파일 업로드만으로 기존 데이터를 즉시 덮어쓰지 않는다.

### 중복 방지

동일한 계약 ID를 가진 자료는 새로운 계약으로 중복 등록하지 않는다.

동일한 거래 기록도 중복 생성하지 않는다.

같은 JSON 파일을 여러 번 가져오더라도 데이터가 중복 증가하지 않도록 한다.

### 충돌 방지

예를 들어 독립 서비스에서 1번 자리 시세를 150권으로 변경했는데 ClassBank 파일에는 이전 시세 120권이 들어 있다면, 자동으로 덮어쓰지 않는다.

다음 선택지를 제공한다.

- 현재 데이터 유지
- 가져온 데이터 적용
- 해당 항목 건너뛰기

변경 시각만으로 무조건 최신 자료를 선택하지 말고, 공통으로 확인된 이전 버전 또는 수정 이력을 기준으로 충돌을 판별한다. 기준이 불확실하면 사용자 확인을 요구한다.

가져오기 실패 시 기존 로컬 데이터를 보존한다.

가져오기 전 자동 백업을 권장하고, 실제 적용은 가능한 한 원자적으로 처리한다.

### CSV 가져오기

CSV 파일에서도 계약이나 자리정보를 가져올 수 있도록 한다.

다만 CSV는 공통 JSON보다 정보가 제한적이므로, 기존 데이터에 없는 필드까지 삭제하거나 덮어쓰지 않도록 한다.

CSV 입력은 지정된 양식에 따라 처리한다.

# PART 12. 로컬 저장과 백업

## 12. IndexedDB

데이터는 IndexedDB에 저장한다.

- 자리정보
- 계약정보
- 거래내역
- 시세 이력
- 자리 배치도 이미지
- 자리 마커 위치
- 설정

새로고침해도 정보가 유지되도록 한다.

단, 브라우저 데이터를 삭제하거나 다른 기기에서 접속하면 자동 복구되지 않는다는 점을 안내한다.

### 백업 기능

JSON 파일을 통한 수동 백업을 제공한다.

배치도 이미지까지 포함한 전체 복원이 필요하면 ZIP 백업 기능을 별도로 제공할 수 있다.

기본 JSON은 ClassBank 호환을 위한 정형 데이터 파일로 사용한다.

배치도 이미지 자체는 공통 JSON에 직접 포함하지 않고, 자리 마커 좌표만 포함한다.

서비스를 다른 기기로 옮길 때 배치도 이미지도 이전할 수 있도록 별도 이미지 가져오기 또는 전체 백업 기능을 지원한다.

# 최종 개발 목표

기존 학급 부동산 소유 현황을 기반으로 자리별 매매·전세·월세 거래정보를 관리한다.

사용자는 자리 배치도에서 특정 자리를 선택해 소유자, 사용자, 시세, 최근 거래가, 계약정보를 확인하고 수정할 수 있다.

모든 자료는 브라우저에 저장되며 JSON 파일을 통해 ClassBank와 양방향으로 교환할 수 있어야 한다.

새로운 백엔드나 금융 기능을 만들지 않으며, 직관적이고 안정적으로 동작하는 독립 부동산 관리 서비스를 완성한다.
